Responsive heroes: phones no longer download the 1920px file

- Every hero now has 640, 1024 and 1600 wide WebP and JPEG variants. Pic takes a
  `widths` prop and emits a srcset with sizes="100vw"; Hero preloads the
  matching width so the fetch starts with the HTML rather than after the
  stylesheet reveals the background.
- Hero weight on a phone drops from 110-225KB per page to 26-58KB: 352KB across
  the eight main routes, down from roughly 1MB. Desktop serves 1600px, a phone
  at 2x serves 1024, at 1x serves 640, all confirmed from currentSrc.
- Hero JPEG/WebP quality lowered to 80/78. The art sits behind a veil at 0.76
  opacity; mean pixel difference against the old file is 1.46/255.

Two bugs found while doing it
- /film and /museum use images that had no variants, so their srcset candidates
  404'd silently. Variants generated for both.
- check-assets.mjs only read single-value src attributes, so it could not see a
  missing srcset candidate. It now parses every candidate in a srcset, which is
  why the reference count jumped from 100 to 148.

Verified: build 30 pages, 148 references, all present. No 4xx on any route
except the Google Maps embed, which the build sandbox blocks.
